01

Project purpose

Author animation exaggeration as a system

The plug-in replaces one-off animation edits with reusable Regions, Modules, and Response Rules. Runtime motion or gameplay signals select an authored response, and GPU compute passes deform the rendered mesh without rewriting the source animation.

01Attach

Add OverAnimComponent and assign a Deformer Asset.

→
02Author

Define Bone Groups and order the Module Stack.

→
03Route

Map signals or automatic phases through Response Rules.

→
04Deform

Execute ordered RDG passes and output the deformed mesh.

Design target

Stable runtime behavior with artist control

Automatic analysis provides timing, direction, and strength, while authored rules decide where and how that evidence changes the mesh. Detection and presentation remain separate.

04

Core logic and troubleshooting

Stability across time, Regions, and threads

The difficult part was not producing a deformation once. It was keeping timing, ownership, and render consumption deterministic while animation evidence changed every frame.

Case 01 · CL 203–272

Suppress false phase transitions

Problem
A one-frame motion spike could open Anticipation or change phase before the movement was sustained.
Cause
An energy threshold alone has no duration, trend history, or cancellation state.
Change
Accumulated onset evidence and required the scaled confirmation time before committing the transition.
Result
Threshold crossings became candidates; temporal evidence decides the actual phase change.
OverAnimMotionPhaseAnalyzer.cppC++
const bool bOnsetConfirmed =
    bCanSeekNewCycle &&
    bHasAnticipationEvidence &&
    State.OnsetEvidenceTime >=
        AnticipationConfirmationTime;

Case 02 · CL 257–272

Prevent Region owner jitter

Problem
Regions with similar scores could exchange ownership on adjacent frames.
Cause
Selecting only the current maximum provided no hysteresis.
Change
Required a 15% relative or 0.02 absolute advantage and confirmed a pending challenger over time.
Result
Small score changes preserve the active owner while decisive motion can still take priority.
OverAnimMotionPhaseAnalyzer.cppC++
constexpr float RelativeAdvantage = 0.15f;
constexpr float AbsoluteAdvantage = 0.02f;
const float RequiredScore = ActiveScore +
    FMath::Max(ActiveScore * RelativeAdvantage,
               AbsoluteAdvantage);

if (!bCounterMotionPriority &&
    BestScore < RequiredScore)
{
    BestCandidateIndex = ActiveCandidateIndex;
}

Case 03 · CL 118–135

Make the Game-to-Render handoff deterministic

Problem
Mutable runtime state could change after a deformation request was created but before the renderer consumed it.
Cause
Analyzer state and asynchronous render work have different lifetimes.
Change
Moved value-owned work items across the render command boundary, then flushed matching Scene and Execution Group work after the MeshDeformer stage fence.
Result
Each RDG submission consumes a stable snapshot without draining unrelated queued work.
OverAnimDeformerTaskWorker.cppC++ / RDG
ENQUEUE_RENDER_COMMAND(OverAnimEnqueueWork)(
    [WorkItem = MoveTemp(WorkItem)]
    (FRHICommandListImmediate&) mutable
    {
        FOverAnimDeformerTaskWorker::Get()
            .EnqueueWork_RenderThread(
                MoveTemp(WorkItem));
    });

FSkeletalMeshUpdater::WaitForStage(
    GraphBuilder,
    ESkeletalMeshUpdateStage::MeshDeformer);

Case 04 · CL 299

Keep visual attachments on deformed endpoints

Problem
A socket-attached visual still followed the undeformed skeleton while Squash & Stretch moved the visible endpoint.
Cause
GPU vertex deformation does not modify the source socket transform.
Change
Accumulated a visual-only component-space offset, transformed it to world space, and restored the previously applied offset before each update.
Result
Registered visuals follow the deformed endpoint without accumulating drift or moving physics targets.
OverAnimDeformerInstanceManager.cppC++
const FVector* Offset =
    VisualAttachmentOffsetsCS.Find(BoneIndex);
if (!Offset || Offset->ContainsNaN())
{
    return false;
}

OutOffsetCS = *Offset;
return true;
